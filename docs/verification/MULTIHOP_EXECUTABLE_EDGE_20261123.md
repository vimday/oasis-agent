## 已落块样本的费用余量

## 首个可双源验证的影子候选

1. **先缩短区块头到完整状态的时间。** Base 八个状态从请求区块头到解码完成用 **659–836 ms**，四个直接子块比父状态晚 **919–1,179 ms** 可用，包含串行请求、主动间隔和解码。驻留扫描在 58 池组中位改善约 **1.4 ms**。Base Denim 的 200 ms 是链上区块时间戳步长。对公开头订阅和现有轮询做同池同源比较，记录本机到达、按哈希取状态、扫描完成、同封装整笔验证及直接子块复价的时钟。漏块和重组按区块哈希、父哈希和状态覆盖处理，补取耗时纳入结果。该窗口 66 池扣费后 0 个正候选并有 62 个未决金额区间，正候选复价和整笔模拟分母均是 0。[Base 前瞻窗口](BASE_RESIDENT_FORWARD_20261123.md) · [Denim 官方说明](https://www.base.org/blog/denim) · [Geth 公开头订阅](https://geth.ethereum.org/docs/interacting-with-geth/rpc/pubsub#newheads) · [按块哈希绑定调用](https://eips.ethereum.org/EIPS/eip-1898)
2. **扩展净额有机会过线的池和路径。** 先用已经核对标准转账与池代码的资产、不同物理池和 2–4 跳，按资金区间内的整数净额排序。剪枝使用毛差上界和成本下界。送整笔复核的候选固定输入、路径和资金，核对本金回收和保守成本，以同一锚定币整数记账。对同一整笔封装记录资产余额差、gas、L1 数据费、适用的 operator fee、融资和失败成本。逐腿报价与整笔时钟分别保留。较长路线和批次只有在计共享储备、调用回滚及整笔费用后仍能闭合才纳入同一经济分母。[最优输入与未决区间](MULTICHAIN_CLOSURE_SIZING_20261123.md) · [OP Stack Operator Fee 规范](https://specs.optimism.io/protocol/isthmus/exec-engine.html#operator-fee)
3. **记下失效的机会，再比较能赶上的净差。** 每个对照固定路线、金额和封装，在首个可核直接子块复算并记盈亏。把被拒绝、过期、未决、报价预算截断和模拟失败都留在漏斗。Base Flashblocks 历史研究在其竞争样本中观测到更高费的失败交易仍可能落在较早的赢家之后。另一项报告试探策略占样本套利活动的 23%，占其归为 spam 的 95%。这两项采用 Denim 之前的数据，当前的排序与失败成本仍需现场测量。后续实验使用公开已成块价格和只读封装模拟，排除抢跑、夹击、刷量和人为制造价差。没有实时正例时，经济命中率和存活率留空。[Base 排序竞争预印本](https://arxiv.org/abs/2610.03922) · [Base 搜索行为研究](https://arxiv.org/abs/2606.00720)
