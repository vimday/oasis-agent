# Ethereum 六跳路线对同一批次贡献多少净额

北京时间 2026-11-27，沿前一轮预先选定的两笔六池 WETH 闭环和一笔高显式付款交易，做了 18 次匿名历史整笔模拟。两条六跳在各自批次中都增加条件净额。单独保留该路线时，第一条盈利，第二条在第一个 Swap 前回滚。把第二条按单路结果筛掉，会漏掉本次实际批次中可核实的增量。[原始持出日和交易清单](BATCH_HUNDRED_CENSUS_20261127.md) · [本轮逐状态数据和哈希](ETH_BATCH_INCREMENTAL_NET_20261127.json)

第二笔删组后，其余 25 个自调用的顺序、calldata、提交日志、返回和 WETH 净变化均相同。单组模拟查询了六个池状态，随后以字符串 `profit` 回滚，耗用 69,351 gas。失败情景为这个 gas 用量乘原费率，实际没有发起交易。合约返回了这一拒绝理由，无法仅凭字符串反推出内部阈值。两笔结果同时说明，重用池状态、整批付款规则和额外 gas 会改变一条路径对组合的价值。[100 事件原交易](https://etherscan.io/tx/0xf99920390d463751870cc42cc8b67b89c05ccc406e55a3b6acc08d04f4df27a0)

## 校准、证据和使用

三个区块分别含 199、151、192 笔交易。复算在内存按原顺序编码全部 542 笔已签交易，逐笔核对哈希、索引和签名恢复的发送者，重建三棵交易树及三棵收据树，与各自块头的 `transactionsRoot` 和 `receiptsRoot` 完全匹配。其中有 532 笔 EIP-1559、8 笔传统交易、1 笔 EIP-4844 和 1 笔 EIP-7702。已落块三例的原包络和执行收据因此均锚定到对应区块和索引。[逐块根与交易类型计数](ETH_BATCH_INCREMENTAL_NET_20261127.json)

免费 dRPC 按块哈希和交易索引模拟。原成交位置的输入、原始完整调用树、提交日志、gas 均与留存成交样本一致。区块时间、费率、gas limit、nonce、账户、value 和 access list 均固定，没有状态覆盖或区块覆盖。成交之后重复原 nonce 只用来检验经济状态，不能据此推断原交易还能被接纳。历史块内结果不能充当前瞻发现时钟。[Geth 客户端的交易前状态](https://github.com/ethereum/go-ethereum/blob/v1.16.5/eth/state_accessor.go) · [debug_traceCall](https://geth.ethereum.org/docs/interacting-with-geth/rpc/ns-debug#debugtracecall)

两笔逐项核对了历史外层字节包、44/47 个不重叠候选记录及实际发起的 30/26 个自调用，原包重编码逐字节相同。删组只移除指定记录，单组只保留它；用未变的调用身份及执行结果验证这个解析。该边界仅对这两份留存交易作实验解释。正常只读历史入口新增 `--self-call-cash`：校对主网 canonical WETH 的转账、包装、解包，核对执行器每个直接自调用首尾两次余额读数，单列回滚和缺少读数。失败分支的日志不参与结算；单个调用帧的 gas 单列，整批额外费用来自两次完整调用差值。[正常入口](../../scripts/replay_eth_tail_case.py) · [资金核对](../../src/oasis_agent/evidence/weth_batch_cash.py) · [回归](../../tests/unit/test_weth_batch_cash.py)

## 四链改动的交付核验

2026-11-27，北京时间 16:01。正常回放现在分别记录自调用本身失败，以及它成功后因整笔回滚而撤销。两种情况下已提交的 WETH 变化均为零。BSC 的日期复算先校验九个留存脚本的固定摘要，新 Ethereum 留出日复算器只读原始字节。独立复算的 Ethereum、BSC、Robinhood 机器记录及 Base 配对结果与留档逐字节相同。
