## 实现

Base 事件报价已有触发块哈希，块头核验和合约调用并行。600 字节 L1 费上界与两腿的输出
金额无关，现在也在同一固定哈希并行查询。轮询先解析最新块，再并行取费与报价；第二腿仍
使用第一腿的整数输出。两臂上限仍为每次四读。失败时清理在途任务，已经预留的额度照计。

`on_time` 继续表示报价腿在 750 ms 内完成。新 capture 的 `net_on_time` 等待同块头、两腿
输出和 L1 费读数，按实际产生模型净额的 `fee_done_ns` 计。收据核验在事后进行。事件中
按时正模型值使用 `model_positive_observed`，超时正模型值使用
`model_positive_after_deadline`。正模型值的截止时间缺失时归为 `incomplete`。
离线回放从原始回包重建三项输入的时间下界，同时兼容原先串行取费的存档。
新计划还要求后一腿的发出时刻晚于前一腿响应、事件日志位置和独立收据一致，并从证据重算
判定。原 `poll_within_deadline` 统计的是时限内开始查询的近邻块，允许更晚的哈希。

本地回归让第一腿等到 L1 费任务开始，把固定块头延迟到截止时间之后。两腿按时、净值模型为
正的构造样本被正确归为迟到。伪造提前的完成时间或准时标签均被回放拒绝。历史 Base 首次
停止、Base 后续窗口和 Elysium 三个留存档案的回放 JSON 在变更前后逐字节一致。旧 Base
事件组两腿按时 2/4，计 L1 费后按时 0/4，四个样本均为负。这个值是旧窗口的基线。现用
模型包含固定 L2 gas、tip 和 L1 费用上界，整笔余额、适用的
operator fee、融资及实际排序属于完整交易的后续验证。

## Base 90 秒只读延迟控制

沿用历史已关闭的固定方向和 0.01 ETH 金额，作为新采集代码的延迟及回放对照。主源为
PublicNode，第二来源为 Base 官方公共 RPC。固定一次 90 秒窗口，事件和轮询各最多四次，
原始账本总上限 92 个公开免费额度，开销 USD 0。每臂分别记录两腿和含费模型的 750 ms
命中数，也记录无回包、缺口、重组和第一处失败。失败即停；无复跑。只读链上调用使用同块
哈希，收尾另核验收据；记录在忽略目录 `reports/research/event-quote-20261123/`。

1. Base 保留同块四池、58 池和 66 池对照，比较公开 `newHeads` 与轮询先收到哪个头。
   用双来源绑定块身份，并行读取两组状态，记录最慢来源、缺块、重组和超时。四个固定块

   发现块上做整笔仿真，再在首个经过核验的直接子块用同一金额和同一调用封装复算。记录
   收到状态、发现、整笔复核和直接子块的单调时间、各阶段净额及失败分母。几十跳以上既
   保存资金串行深度，也为同本金批次保留顺序对照。
