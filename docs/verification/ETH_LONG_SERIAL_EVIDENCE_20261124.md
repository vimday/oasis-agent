## 同块 450 份收据的分流对照

在上述定向样本所在块离线逐笔筛查全部 450 份收据。7 种事件形态共匹配 138 条，
其中 137 条可提取本轮支持的单输入、单输出金额，涉及 82 笔交易。6 笔有至少
5 条可解事件，只有索引 45 的定向样本有至少 10 条。检查可唯一对应、金额完全相同的
直接 ERC-20 池间 Transfer，限制逻辑池互异，并允许回调倒序。这组规则检出的最大
资金依赖深度为 4，≥5 的检出数为 0，其余交易最多有一个这样的连续依赖。路由器持币、
分流合流、Vault 内账、原生币支付和未解协议可隐藏真实依赖。总体资金深度仍有未知，
且该块由定向样本选中，分母仅限该块。

事件数第二高的索引 39 交易提供一笔开放路径对照。它有 **6 条 Swap、6 个不同池和
4 个连续交换阶段**。收据逐笔支持 `385 → {388, 391, 394} → 397 → 400`。先由外层
发送地址付入 4,800,000,000 USDT 最小单位，收到的中间代币全部分给三池，三份输出
又全数合并送往第 5 池。第 5 池产生 8,070,405 WBTC 最小单位，其中 8,070,404 进入
第 6 池。末端的 2,939,108,272,956,592,622 WETH wei 在路由中等额解包。路径首尾资产
不同，交易回执的其余资金归属在本轮保持未决。

## 搜索、金额求解与批次验证

- **发现与归因。** 对连续状态增量，TRADER 的动态负环检测及受影响边组合适合减少重复粗筛，
  可以在存量 Rust 图上配对测试。图边绑定链、块哈希、币范围和池身份。对 ≥10 的长尾，
  保留弱拓扑上界、边际证书和残余搜索。历史成交归因按调用树和资金事件检验。2026 年
  资金结构等价预印本给出了转账树化简和形式化守恒，可用于比对，协议支持范围、受益地址和
  费用维度仍需各自复核。[TRADER 作者代码](https://github.com/Xtra-Computing/TRADER) · [资金结构等价预印本](https://arxiv.org/abs/2608.20377) · [存量图基线](MULTIHOP_RESIDENT_GRAPH_20261123.md)
- **长尾候选与整数金额。** RICH 优化固定跳数的简单负环，其独立染色命中一条固定简单环的
  单轮概率为 `k!/k^k`。按其失败概率公式计算，覆盖单条固定环达到 95% 时，10 跳需 8,254
  轮，20 跳约 1.29 亿轮。论文正文图 9 的计时范围为 3–6 跳。图中的边际最佳与扣费后
  有限金额最佳需要各自测量。对给定
  无重池 V2 路线，连续复合报价可构造上界，再以逐腿取整和工作预算给出已验证净额与
  未决上界。存在分拆或多市场组合时，CFMM 连续松弛可用于候选或适用假设内的上界，
  每池固定成交成本引入混合整数选择。V3 区间、V4 Hook 和合约状态需要独立校验。
  [RICH 论文 §3](https://www.vldb.org/pvldb/vol18/p4081-luo.pdf) · [CFMM 路由与固定费用](https://arxiv.org/abs/2204.05238) · [多池分解算法](https://arxiv.org/abs/2302.04938) · [本地整数定量](MULTICHAIN_CLOSURE_SIZING_20261123.md)
- **同一资金的批次。** 先比较同一规范状态和同一资本的最佳单笔、各闭合组独立报价以及
  共享池状态下的有序批次。每个成功组写入后续可见的储备、余额和融资状态，失败组按
  合约语义回滚并保留其成本。整笔费用、外部支付和偿还义务从完整 envelope 核算。
  BSC 保留的乐观费用实验排除 FLOKI 后，独立报价合计 +355,373,261,683 BNB wei，
  有序批次为 −377,509,353,086 BNB wei。仅改变共享池状态的处理已足以翻转净额。
  复核按固定交易顺序保留的前态需要包含同块更早的交易，再测下一次收到的规范状态和迟到率。
  [BSC 配对结果](BSC_V2_BATCH_COMPARISON_20261123.md) · [前态回放](MULTIHOP_PRETRADE_REPLAY_20261123.md)
- **GPU 以窗口内保留净额衡量。** MeVisor 对 3,941 个历史 MEV 案例的数字是其 GPU 原型
  吞吐，覆盖不止一种策略，不能直接读成真正串行深度或实时完整成本净额。本地 50,000 条
  已给定合成路线用 8 个 CPU 线程直接精算 p50/p99 为 1.474/2.680 ms，GPU 筛选加 CPU
  精算为 1.701/2.427 ms，512 和 5,000 条时 CPU p99 更短。下一轮配对从首次收到可核验
  的规范状态开始计时，同批比较 CPU 直算、CPU 筛选和 GPU 筛选，纳入上传、同步、精算、完整
  仿真、候选过期和残余。量化各臂在截止时间前保留的已验证净额，测出 GPU 适用的批量。
  [MeVisor 指标口径](https://www.ndss-symposium.org/wp-content/uploads/2026-f93-paper.pdf) · [本地 GPU 与 CPU 复测](MULTIHOP_CUDA_20261122.md)
