正常只读入口增加 `replay_swap_flow --transfer-splits`。它先取得原来的严格全额资金证明，另输出由调用、代币余额及三份唯一转账日志核实的净额资金连接。这个窄规则要求留存接收方是代币合约本身。还要逐池核对交换前两项储备、池在交换内对两个实际币种所作的余额查询、规范顺序的 Sync 与 Swap。实际两池在日志 240、248 同步储备，前池的币侧减少量等于完整收入，后池的增加量等于扣减后的 837,358,902,661,763,506,257。负例中另一个币向同地址转入同样金额，只有这种逐币核验能识别多余付款。21 事件样本补出日志 241 → 249，10 事件对照未添任何边。该规则核对观察到的两池会计动作，其他运行码的协议身份、未来到账及执行资格仍待独立核对。[回放入口](../../scripts/replay_swap_flow.py) · [资金证明](../../src/oasis_agent/evidence/swap_transfer_splits.py) · [正负控](../../tests/unit/test_swap_transfer_splits.py) · [V2 储备、余额及事件规范实现](https://github.com/Uniswap/v2-core/blob/816075049f811f1b061bca81d5d040b96f4c07eb/contracts/UniswapV2Pair.sol#L159-L175)
