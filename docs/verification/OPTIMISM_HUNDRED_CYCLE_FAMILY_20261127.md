## 资金角色和原生余额对照

首轮前，签名发送者将 0.02／0.03／0.02 原生 ETH 交给执行器。三笔的回执日志 0 均是执行器将完全相同金额包装为 WETH，日志 1 随后向首池支出。每轮中间的 USDC.e 通过执行器等额出入，对应两条实际转账。后池的 WETH 返款先到执行器，随后由执行器解包。第一轮解包日志 11 与第二轮包装日志 12 的原始金额一致。全部跨轮匹配都有相同账户、先解包后包装、精确整数相等和无其他执行器 WETH 操作插入的证据。最后三次解包分别为日志 557／583／599。将 `Deposit` 和 `Withdrawal` 与 `Transfer` 一起计入后，执行器的 WETH 与 USDC.e 变化均为零，不能留用仅由 `Transfer` 算出的 WETH 差额。观察到的流水从零初始 WETH/USDC.e 即可完成。[Optimism WETH9 预部署](https://github.com/ethereum-optimism/specs/blob/main/specs/protocol/predeploys.md)

按可见资金逐轮重建，如果没有其他原生币转入，要用独立期初库存代替某次前轮返款，至少需要该轮包装量；如果所有解包都不能用于后轮，三笔分别需签名本金之外 **1,039,524,596,466,082,099／1,546,570,915,150,472,203／1,005,292,766,216,994,173 wei**。这两个阈值用于区分已证资金次序和可替代性。旧原生库存及日志未覆盖的内部原生币转移，单靠回执不能排除。机器记录为每轮保留阈值和确切日志索引。

额外以原块头中父哈希及目标哈希，对同一执行器查六次 `eth_getBalance`。dRPC 全部回复 `0x0`。一个同年代、同发送者和执行器的 136 事件正控中，同一端点同样声称发送者在父块只有 0 wei，而该块唯一成功交易的已恢复签名发送者实际提供了 30,000,000,000,000,000 wei。故本次六个零值只保留为提供者读数，不建立期初余额或余额净变化事实。若零值确实有效，执行器期初旧 ETH 无法替代紧接的前轮返款，且末态零与可见流水之间分别需要抵销整个末轮解包量的原生币净流出。这些都是条件推论，原生币确切终端收款者及共同控制未知。[同端点 136 事件正控](OPTIMISM_136_REINVESTMENT_20261127.json)
