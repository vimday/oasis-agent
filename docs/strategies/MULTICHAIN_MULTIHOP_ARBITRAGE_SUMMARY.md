## 下一轮如何决定把时间投在哪里

1. **BSC 优先补真实成交缺口。** 保留 115 池对照，按成交中的交易所、工厂、池 ID 和实际到账加入候选。先补已知长路首次跨 tick 的缺页与税后金额，每头同时报新增可完整报价的路线、通过费用的候选数，以及同窗成交中覆盖了多少条实际资金边。
2. **Base 优先抢回一个可用状态。** 四池作持续基线，58/66 池另计。用同一连续头测按最新头调度、优先读取变动 V4 池、提前取独立见证。全量复算核对相同哈希和整数输出，按直接子头以及 200 / 750 / 2,000 ms 各报交付数。只有端到端改善才把实验合入实时默认路径。
3. **Ethereum 同时搜长串行和可还款短环组合。** 对不同日期的完整块分别按事件数和唯一金额连接排名，保留随机背景、低解码和失败样本。候选要经过币种、金额、归属和偿还次序复核。历史潜在赢家在交易前状态比整批、删组和单组。前瞻候选独立冻结输入，再记 H/K/C 与全成本区间。
4. **Robinhood 用方向容量筛长路。** 用首段的真实到账逐腿推进，在同一块核对 tick、价格、手续费和可用流动性。跨 tick 后还有流动性才继续计算。报价器拒绝和缺页分别标记。选出的可编码整路仍需双源整笔、原发送者估费与退款见证。
5. **以每个截止时间内增加的可验证净额决定算力和数据预算。** 现有 Rust 跑图与整数热循环，Python 负责独立核对与证据编排。Aleph 4070 Ti 在现有五万条预给定短路线基准里，相对八线程 CPU 的 p99 改善 9.43%。先用相同真实状态、路线、额度比较含传输及复核的端到端结果。匿名数据已经能做发现、整笔与历史归因。是否值得付费，取决于能多交付多少及时完整的结果、以及新增净额能否覆盖数据成本。[GPU 实测](../verification/MULTIHOP_CUDA_20261122.md) · [Rust 分工](../verification/MULTIHOP_RUST_BOUNDARY_20261123.md)

固定调用成本会改变最优场所组合，CFMM 路由研究给出了含固定成本的混合整数模型。MeVisor 在论文环境中用 GPU 并行评估大量候选。对 Oasis，可用连续模型做乐观上界剪枝，用 GPU 批量生成和排序候选，再用整数、整笔支付与真实到达时钟验收。两者都需要在本项目数据上衡量经济召回。[CFMM 路由论文](https://arxiv.org/abs/2204.05238) · [MeVisor 论文](https://www.ndss-symposium.org/ndss-paper/mevisor-high-throughput-mev-discovery-in-dexs-with-gpu-parallelism/)
