# 多链发现与借贷价差实验

设计锁定：2026-11-14，基线提交 `78eb13e`；作者与内部复核：Codex（非独立审核）。
范围：公开提供者观察与合成场景；没有链上执行、付费 RPC 或资本授权。

## 假设及反证

同一 EVM 研究引擎可以按 chain ID 处理 Ethereum、Base、Robinhood、Elysium，
但资产地址、部署、排序、最终性、费用及 oracle 必须独立验证。第一项交付是固定四链、
每链至多 32 池、无分页/重试的 Metric 目录采集与离线发现；总共至多四个公开 HTTP 请求。
完整列表、流动性及可交易性均不能从目录推定。跨链同名币不组成原子路径。

第二项假设：拥有者卖出已有 ETH，抵押所得稳定币，借 ETH 再卖，可能捕获链上卖价相对
债务估值的溢价；实际利润取决于退出买价、偿还本金与利息、成本及资本占用。
卖出借款不创造无负债收入，oracle 估值不等于可执行买回价。

## 固定设计

- 不搜索最佳参数。新增引擎只做单一抵押品、单一债务资产的整数场景；不支持 eMode、
  isolation、信用委托或完整协议模拟。输入必须显式声明资产、精度、USD oracle 价格、
  sell/buy 价格与总容量、LTV/LT、供借 cap 剩余量及借款可用量。
- 每次抵押、借款和出售受同一总容量约束。循环至指定轮数、冻结或容量耗尽；不允许
  将每轮当作全新深度。入场价是费用和滑点之后的保守统一成交界，不是无限深度报价。
- 借款容量向下取整，债务和买回成本向上取整。债务增长因子为明确的压力假设，
  不是协议利息指数回放；存款利息不计入收益。所有本金、现金、抵押与债务独立保留。
- 退出只建模预置现金买回、偿还后撤回抵押品的顺序。现金不足、暂停、撤款流动性不足、
  买回深度不足、HF < 1 或未知成本必须阻止“可退出”结论。闪电贷退出没有默认授权或实现。
- 基准包括持有原始 ETH 和稳定币，以及仅卖出初始 ETH 后持有现金；相同外部退出准备金
  和时间窗口，成本单列。累计卖出额、抵押品总额均不是 NAV。
- 例子覆盖收敛、溢价持续、oracle 上跳、稳定币脱锚、借款冻结、成本未知和退出资金不足。
  所有数值是测试假设，不能作为 2026-10-29 历史价格或收益证明。

## 数据与验收

目录为发现窗口；地址线索为事件调查。尚无校准、独立验证或 untouched test window，
不报告胜率、年化、置信区间、历史回撤或可投规模，也不提升策略等级。
测试接受条件：四链隔离；拒绝重复/冲突元数据；保留缺失与失败；请求上限固定；捕获
防覆盖及哈希可回放；借款/资产守恒；整数精度变换一致；限制和退出失败不得伪造净收益。
部署检查、原始交易与收据、精确 prestate、双源 oracle 和整笔模拟留到下一阶段。

结果和纠错另见[验证记录](../verification/MULTICHAIN_LENDING_20261114.md)。

## 下一阶段的具体交付顺序

多链研究同时推进，Base 保留现有有界运行验收边界，Robinhood 保留 LP 基准。
链 ID 是研究接口的参数，不是新链交易授权。新增链不应复制一套策略或共享余额。

| 交付 | 本轮已具备 | 下一项证据/代码验收 |
| --- | --- | --- |
| 链与 venue 目录 | 四链有界目录入口、严格解析、反向 token 顺序保留、同链相同资产聚类 | 对每链建立 runtime/proxy/config 身份及独立 RPC 能力档案；Base/Elysium 的 Metric HTTP 缺口用经预算的 factory/事件索引补足 |
| 机会触发 | 既有 Elysium 事件研究与 Metric 双池离线深度筛选 | Swap/LP 变动、maker 更新、oracle 更新、借款利用率/cap/freeze 共同唤醒；去重按 chain/block hash/event，重组与断线保留缺口 |
| 报价与规模 | 单提供者 Metric 深度及累计容量；借贷循环容量/HF 场景 | Metric 加独立 DEX 同链两腿；保留更新前后状态；验证真实 sender/recipient/extension、实际 input delta、失败成本 |
| 历史事件回放 | 用户地址线索、公开研究口径核对、源码固定、合成压力计算 | 给 `0x0cdd…661d8` 建完整借/卖/抵押/买/还/撤账本；取得 Elysium 赢家精确 prestate，逐笔模拟并纳入失败者和资金流出 |
| 前瞻 shadow | 现有统一证据/账本基础；不增加 signer 权限 | 先冻结每链池范围、窗口、规模网格及请求预算，再报告事件覆盖、检测/报价/模拟延迟、完整路径占比、失效原因和扣成本机会；未覆盖窗口不算无机会 |
| 独立执行准入 | 既有 Base 风控与 signer 分离 | 仅当具体策略通过独立完整 NAV、风险及双源精确交易模拟后另行验收；分别核定资本与 RPC 预算 |

首个前瞻实验优先对照“事件触发”和“相同预算定时全扫”；以完整闭环证据的覆盖和延迟
决定哪个触发器值得保留，而不是用报警条数评价。候选策略共享发现/证据接口，风险、
库存与债务分别记账。LP 收益、同链 taker、借贷融资、稳定币/包装资产兑换都纳入目录，
并按所需证据逐项提升；新闻与钱包追踪提供线索，不能自动触发资金操作。

## 本轮可运行入口

```sh
# 显式四链探测；遇到不支持的 API 会退出 3 并保留原始失败，不继续或重试。
.venv/bin/python -m scripts.discover_metric capture \
  --plan configs/metric-universe.example.json --out /tmp/metric-universe-new
# 仅完整捕获可回放。错误/部分捕获退出 2，不发布成功报告。
.venv/bin/python -m scripts.discover_metric replay \
  --capture /tmp/metric-universe-new --output /tmp/metric-universe-report-new.json
.venv/bin/python -m scripts.research_lending_loop \
  --plan configs/lending-loop.synthetic.example.json --output /tmp/lending-synthetic-new.json
```

所有路径必须尚不存在。公开采集使用固定 `api.metric.xyz`、无认证、无重试、无分页，
每响应最多 2 MiB、每计划至多 8 链；默认四链每链 32 池。请求/响应/时钟/计划哈希随
捕获保留，输出文件原子发布且不覆盖。目录只供发现，没有可执行报价或 PnL。
`requests`/`discover` 可用于离线输入；现有 `research_metric` 保留定向双池深度入口。
目录可聚合两个 token 顺序不同的池，但必须按保留的原方向构造报价；现有双池深度
计划仍要求相同有序资产对，不自动把反向池转换成可运行计划。

借贷例子使用虚构 SYNUSD/SYNETH 地址及参数；20,000 SYNUSD 退出准备金与 1 SYNETH
初始库存仅用于压力测试，不改变真实 USD 500 资本上限。报价以 collateral raw / 整个
debt token 为单位，oracle 统一 USD 8 位。`exits` 是替代压力场景，不可相加成收益。
`hold_baseline_raw` 按退出 ask 计算恢复原始债务资产库存的成本；sell-only 是只卖出
初始库存并持有稳定币的成本前基准。相对两个基准的超额均扣全部声明成本，属于保守比较。
`gross_marked_equity_raw` 即使为正也未证明可退出；仅无阻断条件时提供条件终值。
